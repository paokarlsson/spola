fix(config): skip a leading UTF-8 BOM in configuration files

Source.file and Source.optionalFile now ignore a byte-order mark at the
start of a file, so a BOM-prefixed inventory.properties no longer drops
its first setting. The demo now reports a non-UTF-8 order file as a data
error with a line number, and the I/O error mapping and quantity parsing
are tidied up.
