fix(security): upgrade hashes only if the verified hash is still stored

PasswordUpgrade.upgrade now gets the verified hash and InMemoryUserStore
replaces only that exact hash, so an upgrade can no longer write back an
old password after a change. A known user with an unreadable stored hash
gets BAD_CREDENTIALS after one dummy check and a class-name-only WARNING,
not a 500. New PBKDF2 hashes are at most 32 bytes; the timing caveat
across algorithms is documented.
