fix(client): hide Authorization credentials and refuse dot segments

For Authorization and Proxy-Authorization the text after the scheme,
and for Basic the decoded user:password and password, now count as
secrets, so a server that echoes just the key no longer leaks it. A
new safeExcerpt() gives the hidden excerpt for log lines, the docs warn
about the JDK's HTTP client logging, and "." or ".." path segments are
refused.
