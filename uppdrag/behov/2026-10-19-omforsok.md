# Omförsök vid tillfälliga fel (motsvarighet till Spring Retry)

Projekt: psykologen (paokarlsson/psykologen), backend som har gått över från Spring Boot till Spola
Spola-version: 0.2.0

## Behov
Psykologen anropar Anthropics Messages API med `spola.client`. API:t svarar ibland 529
(overloaded), 429 eller 5xx, och då ska anropet göras om några gånger med väntetid emellan i
stället för att samtalet får ett fel. Anthropics Java-SDK, som appen använde innan, gjorde det
själv (två omförsök med exponentiell väntetid och `retry-after`). Utan det i Spola måste varje
app skriva samma loop, och lätt få fel på vilka fel som är tillfälliga.

## Motsvarighet i Spring eller Lombok
Spring Retry: `RetryTemplate` (`RetryTemplate.builder().maxAttempts(3).exponentialBackoff(...)
.retryOn(...)`), `@Retryable` och `@Backoff`. I Spring Framework 7 också
`org.springframework.core.retry.RetryTemplate` och `RetryPolicy`.

## Användningsfall
```java
// Namnen är förslag, planeraren bestämmer.
var retry = Retry.builder()
        .maxRetries(2)
        .backoff(Duration.ofMillis(500), Duration.ofSeconds(8))   // exponentiell, med lite slump
        .retryOn(e -> e instanceof RestClientResponseException r
                && (r.status() == 429 || r.status() == 529 || r.status() >= 500))
        .delayFrom(e -> e instanceof RestClientResponseException r
                ? r.headers().firstValue("retry-after").map(s -> Duration.ofSeconds(Long.parseLong(s)))
                : Optional.empty())                                 // serverns väntetid går före
        .build();

MessagesResponse response = retry.call(() -> anthropic.post("/v1/messages")
        .json(request, MessagesRequest.CODEC)
        .retrieve(MessagesResponse.CODEC));
```

Acceptans för appen: anropet ovan mot en `HttpServer` som svarar 529 med `retry-after: 2` och
sedan 200 ger svaret efter en väntan på 2 s; tre 500 i rad ger det sista felet efter två
omförsök; 400 och en utgången tidsgräns försöks inte igen. Väntan går att byta ut i tester så
att de inte behöver vänta på riktigt.

## Krav som inte syns i koden (valfritt)
- Väntan sker med `Thread.sleep` på den virtuella tråd som anropar, och ett avbrott avbryter
  omförsöken.
- En väntetid från servern har ett tak (en minut), så att ett elakt `retry-after` inte låser
  en tråd.
- Bara JDK:n. Hör hemma i en egen modul eller i `spola.util`, inte i `spola.client`, så att det
  går att använda för annat än HTTP.
